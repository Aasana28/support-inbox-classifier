\## 3. Tech stack (fixed, do not change)

\- Next.js (latest stable, App Router) + TypeScript + Tailwind CSS. Font: Inter via next/font. Allowed extras: lucide-react (icons), recharts (charts), papaparse (CSV), zod (validation). Avoid heavy UI libraries.

\- All AI calls happen server-side in Next.js route handlers (app/api/\*\*/route.ts). API keys must never reach the browser. Set export const maxDuration = 60 on AI routes.

\- Text generation: Groq via the groq-sdk package. Model from env GROQ\_MODEL (value: openai/gpt-oss-120b; backup: openai/gpt-oss-20b). Request JSON output where structure is needed, validate it with zod, retry once on invalid JSON.

\- Embeddings: Gemini via the @google/genai package. Model from env EMBED\_MODEL (value: gemini-embedding-001) with outputDimensionality 768. Vectors of 768 dimensions are not normalized, so L2-normalize every vector. Use taskType RETRIEVAL\_DOCUMENT for documents and RETRIEVAL\_QUERY for queries (CLUSTERING or CLASSIFICATION where relevant).

\- Env vars live in .env.local (already created by me; never overwrite it, never print or log its values). Also create .env.example with placeholder values.

\- Vercel is serverless and stateless: never write to disk at runtime. Static data lives in the repo (/data). Precomputed embeddings are generated by a script (npm run build-index) and committed as JSON.



\## 4. No data storage

No database, no localStorage / sessionStorage / cookies for app data, no server-side persistence. State exists only in React state for the current session. Uploaded files are processed in memory and never saved. State this in the README and in a small UI footer note.



\## 5. AI behaviour rules

\- Anything computable by code (counts, percentages, changes, scores, filters, thresholds) is computed by code, never by the LLM. The LLM only classifies, summarizes, drafts or explains using the data it is given.

\- The LLM must use only the provided context and must say so when the context is insufficient. Never invent facts, numbers, sources or quotes. Validate in code that every cited source or quote really exists in the provided context; drop or flag anything that does not.

\- Handle API errors, rate limits (429) and timeouts gracefully: retry once, then show a clear friendly message in the UI. Never show a blank screen or a raw stack trace.



\## 6. SHOW THE WORK (most important UI principle)

The UI must make all the work the system does visible to the evaluator instead of hiding it in the backend. For every AI or data operation show: the inputs used, intermediate results (retrieved sources with scores, rules triggered, computed numbers, thresholds with pass/fail), the model output, and status/timing. Use one consistent pattern: a "How this was produced" (processing trace) section next to each result, written in plain language. Show real per-step loading states while processing. Every requirement in the project definition must be demonstrable in the UI without opening the code.

\- Every screen needs designed empty, loading, error and success states (skeletons or spinners with step text).
